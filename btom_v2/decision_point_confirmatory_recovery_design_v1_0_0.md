# Confirmatory compositional-stratum recovery v1.0.0

This one-shot operational recovery filters the frozen 432-prompt confirmatory order for `difficulty == "compositional"` and executes all 144 selected prompts. It does not backfill cells, reuse any previous compositional response, consolidate the confirmatory dataset, or perform scientific inference.

Direct and irrelevant-distractor variants remain sourced wholly from attempt 3. Every compositional variant is sourced wholly from `compositional_recovery_1`; compositional observations from attempts 1–3 are discarded. The primary paired contrasts remain within variants and within collection batches.

The recovery creates a batch-by-difficulty association. This limitation must be reported, and no inferential comparison between difficulty strata is authorized. Difficulty subgroup comparisons are descriptive only.

## Dual-account routing preparation

The second recovery batch uses a prospectively frozen variant-level assignment: instance 5 of each family × surface-domain archetype is assigned to the public `primary` slot and instance 6 to `secondary`. Each slot therefore receives 12 whole variants, 72 prompts, six variants per family, one variant per family × archetype, and balanced A/B/C/D execution patterns. Assignment is independent of all prior outputs and preserves canonical prompt order.

Credential failover is authorized only for a structured HTTP 429 that clearly identifies tokens-per-day exhaustion. On that pre-inference event, every partial transport response for a variant routed through the exhausted slot is discarded and the complete six-prompt variant is replayed with the remaining slot. RPM, RPD, TPM, ITPM, OTPM, generic 429, transport errors, parsing failures, incomplete generations, and illegal actions never trigger account switching. Outputs from attempts 1–3 and recovery run 30581466480 remain excluded.
